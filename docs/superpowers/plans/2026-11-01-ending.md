# The Ending Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Journey's ending from spec §6. In Stockholm the walk stops on the evening quay and the avatar turns around to face the viewer for the first time. The path ahead fades out unbuilt, and Eduardo's contact options appear under an invitation to be part of the next chapter. The stage header shows all four cities completed.

**Architecture:** The ending is the last 0.5 screens of the Journey. Stockholm grows from 1.5 to 2 screens, so its projects keep their current spacing; the total becomes 9 screens, still inside the 8–10 budget. The timeline gains an `ending` overlay. Pure pose functions stop the avatar at the quay, turn it around and frame it. A scene component draws the fading "unbuilt" path ahead. The overlay renders the ending copy and contact links from one content module.

**Tech Stack:** As plans 1–2 (Next.js 16.4.3, R3F 9.8.2, drei 10.7.9, three 0.187.0, Vitest 5.0.5, Playwright 1.64.1).

**Spec:** `docs/superpowers/specs/2026-11-01-portfolio-website-design.md` (§6 "The ending" and "Length budget", §10, §11 items 4–5)

**Builds on:** plan 1's `SEGMENTS`/`TOTAL_SCREENS`/`overlayAt`/`stageProgress`, `pathPoint`/`pathTangent`/`cameraPose`/`distanceAt`/`PATH_LENGTH`, and `StageHeader`/`JourneyOverlay`/`StandInCities`. Plan 2's `avatarPose`/`cameraPoseAt`/`headingAt` in `src/journey/voyage/poses.ts`.

## Global Constraints

- Length budget: Stockholm becomes 2 screens, so the total is 9 screens (spec §6 allows 8–10, "revisit after projects are placed"). The ending is the last 0.5 screens, from 8.5 to 9.
- Contact: email `eduardoluisvp99@gmail.com`; LinkedIn `https://www.linkedin.com/in/eduardopereira-/`. The CV download only appears once a PDF exists (spec §11 item 5). Until then it's hidden, never a broken link.
- Ending copy is placeholder (spec §11 item 4): title `The next chapter starts here.`, line `Want to be part of it?`. Both live in one content module.
- External links open in a new tab with `rel="noopener noreferrer"`.
- Navigation (header, Projects, About) stays visible during the ending. The Projects button is the "way back to the projects" (spec §6).
- The ending must work scrolled in reverse, and with reduced motion. It's scroll-driven, with no timers.

## Review Focus

1. **Scrolling past the end** (overscroll, trackpad bounce): the avatar stays on the quay facing the viewer and never walks into the unbuilt path. The ending stays on screen. Test in Task 2.
2. **Scrolling back out of the ending:** the avatar turns back around and resumes walking, and Stockholm's last project reappears. Tests in Tasks 1 and 2.
3. **No CV PDF yet:** no CV button and no dead link. Test in Task 4.
4. **The LinkedIn link** must not give the opened page access to this one. Test in Task 4.
5. **All cities completed at the end:** the header must not show Stockholm as still "in progress". Test in Task 5.

### Task 2: Ending poses: stop on the quay, turn around, frame the face

**Files:**
- Modify: `src/journey/path.ts` and `src/journey/path.test.ts`, `src/journey/voyage/poses.ts` and `src/journey/voyage/poses.test.ts`

- Consumes: `ENDING_START`, `ENDING_SCREENS` (Task 1).
- Produces:
  ```ts
  // path.ts
  export const QUAY_END: number;                         // distanceAt(ENDING_START) = 340
  export function pathPointExtended(d: number): Vec3;    // pathPoint for d ≤ PATH_LENGTH; beyond it, straight on along the end tangent
  // poses.ts — ending behaviour added to the existing functions
  avatarPose(s)  // s ≥ ENDING_START: position pathPoint(QUAY_END); heading headingAt(QUAY_END) + π·easeInOut(min(t/0.6, 1)); walk = QUAY_END (idles)
  cameraPoseAt(s) // s ≥ ENDING_START: blend(cameraPose(QUAY_END), FACE, easeInOut(t)) where FACE = { position: cameraPose(QUAY_END).position − tangent·2 + (0,−0.6,0), target: pathPoint(QUAY_END) + (0,1.5,0) }
  ```

  - `avatarPose(8.8).heading` is close to `headingAt(340) + Math.PI` (the turn is complete by 60% of the ending).

  - **Review Focus 2:** `avatarPose(8.4).position` equals `pathPoint(336)` (walking again, the turn undone), and its heading is close to `headingAt(336)`.
