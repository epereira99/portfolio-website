# The Voyage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stand-in "walk across the water" between Porto and Jönköping with the voyage from spec §6. The avatar boards a 1500s nau moored on the Douro, and the camera pulls up into a parchment map of Europe where a dotted route draws itself from Porto to Jönköping as you scroll. The camera then dives down into Jönköping, where a banner reads "Välkommen till Jönköping, och AI".

**Architecture:** The voyage segment (screens 3.5–5, from plan 1) gets its own pure phase function: board → liftOut → sail → diveIn. Pure pose functions derive the avatar position, the nau position and the camera from the phase. Avatar and CameraRig switch from raw path math to these pose functions. The map is a DOM/SVG overlay (not WebGL), so it also works without 3D. Its land outline and route are generated once by a script from Natural Earth data and committed as a TypeScript module. The nau is a Blender-scripted glb, like the avatar.

**Tech Stack:** As plan 1 (Next.js 16.4.3, R3F 9.8.2, drei 10.7.9, three 0.187.0, Vitest 5.0.5, Playwright 1.64.1, Blender 5.2.2). New dev-only dependencies for the map generator: d3-geo 3.1.1, world-atlas 2.0.2, topojson-client 3.1.0, @types/d3-geo 3.1.1, @types/topojson-client 3.1.5.

**Spec:** `docs/superpowers/specs/2026-11-01-portfolio-website-design.md` (§6 "The voyage", §7, §10)

**Builds on:** plan 1 (`docs/superpowers/plans/2026-11-01-foundation-and-journey-skeleton.md`): `SEGMENTS`, `segmentStart`, `pathPoint`, `pathTangent`, `cameraPose`, `distanceAt`, `UNITS_PER_SCREEN = 40`, `getScreens`/`useScreens`, `Avatar`, `CameraRig`, `JourneyCanvas`.

## Global Constraints

- The voyage is the screens 3.5–5 segment (1.5 screens). The length budget does not change (spec §6).
- Banner text, exactly: `Välkommen till Jönköping, och AI`. Keep it in one constant: its wording is open (spec §11 item 1).
- The route is a simple stylized line, not a geographically exact canal route (spec §6).
- Map look (spec §6, §7): parchment, sepia tones, a compass rose, hand-drawn feel. It is the only non-3D-world visual.
- The nau (spec §6): a 1500s Portuguese nau with three masts and square sails bearing the red Cross of the Order of Christ, in the Townscaper-like soft, rounded style (spec §7).
- Water only where it is real (spec §7). The nau is moored on the Douro, on Porto's water side (the walker's right).
- Navigation (stage header, Projects, About) stays visible during the whole voyage, map included (spec §3).
- All motion respects `prefers-reduced-motion` (spec §5). The route reveal is driven by scroll, not by a timer.
- Distances: Porto ends at d = 140; Jönköping starts at d = 200 (screens × 40).

## Review Focus

1. **Scrolling backwards through the voyage:** the avatar gets off the ship and stands back on Porto's path. Never stuck on deck in Porto, never floating. Test in Task 5.
2. **Jumping or flinging past the voyage** (chapter bar "Jönköping", a fast scroll): no map left over on screen, and the avatar in Jönköping, not on the ship. Tests in Task 1 and Task 5.
3. **A narrow portrait phone (375×812):** both "Porto" and "Jönköping" are on screen, and so is the whole route. Test in Task 8.
4. **No WebGL:** the map still appears during the voyage and the route still draws. Test in Task 4.
5. **Reduced motion:** the map still appears and the route still draws with scroll, but with no decorative animation (ship bobbing). Test in Task 4.

**Interfaces:**
- Consumes: `segmentStart`, `SEGMENTS` (plan 1 timeline).
- Produces:
  ```ts
  export type VoyagePhase = 'before' | 'board' | 'liftOut' | 'sail' | 'diveIn' | 'after';
  export type VoyageState = { phase: VoyagePhase; t: number; mapOpacity: number; routeProgress: number };
  export function voyageState(s: number): VoyageState;
  ```
- The voyage-local position is v = (s − 3.5) / 1.5. The phase windows in v are board [0, 0.15), liftOut [0.15, 0.30), sail [0.30, 0.80) and diveIn [0.80, 1.0). Below 0 the phase is 'before'; at 1 and above it is 'after'. Within a phase, t runs from 0 to 1; 'before' and 'after' have t = 0.
- `mapOpacity` is 0 until v = 0.20, rises linearly to 1 at v = 0.30, holds at 1 until v = 0.80, falls linearly to 0 at v = 0.90, and is 0 after that.
- `routeProgress` is 0 before the sail, equals t during the sail, and is 1 after it.

### Task 5: Voyage poses (avatar, nau, camera)

**Files:**
- Create: `src/journey/voyage/poses.ts`, `src/journey/voyage/poses.test.ts`

**Interfaces:**
- Consumes: `voyageState` (Task 1); `pathPoint`, `pathTangent`, `cameraPose`, `distanceAt` (plan 1).
- Produces:
  ```ts
  export const PORTO_END = 140; export const JONKOPING_START = 200; // path distances
  export const DECK_HEIGHT = 2.2;                 // must match the nau model's DeckSpot (Task 6)
  export type Pose = { position: Vec3; heading: number };   // heading = rotation.y; 0 faces +Z
  export function headingAt(d: number): number;   // Math.atan2(tx, tz) of pathTangent(d)
  export function nauPose(s: number): Pose;
  export function avatarPose(s: number): Pose & { walk: number }; // walk = distance fed to walkClipTime
  export function cameraPoseAt(s: number): { position: Vec3; target: Vec3 };
  ```
- **Moored nau:** its centre is at `pathPoint(140) + n·7`, where n is the unit normal pointing to the walker's right (`[-tz, tx]` normalized, the same convention as plan 1's `standIn.ts`), with heading `headingAt(140)`. During liftOut it sails forward along the tangent by `12·easeInOut(t)`. From the sail onward it stays at that final position. Outside the voyage it stays moored.
- **Avatar:**
  - 'before' and 'after': at `pathPoint(distanceAt(s))` with heading `headingAt(d)` and walk = d.
  - 'board': three points, A = `pathPoint(140)` (y 0), B = A + n·4 (y = DECK_HEIGHT, the top of the gangplank) and C = the nau deck spot (`nauPose(s).position` with y = DECK_HEIGHT). The avatar goes A→B over t ∈ [0, 0.6] and B→C over [0.6, 1], heading toward the next point, with walk = 140 + the distance covered so far.
  - 'liftOut': on the deck spot of the moving nau, with the nau's heading. walk is held at its board-end value, so the avatar idles.
  - 'sail' and 'diveIn': at `pathPoint(200)` with `headingAt(200)` and walk = 200. The avatar is already waiting in Jönköping, hidden behind the map.
- **Camera:**
  - 'before', 'after' and 'board': `cameraPose(distanceAt(min(s, 3.5)))` while boarding, and `cameraPose(distanceAt(s))` otherwise.
  - 'liftOut': eased interpolation from `cameraPose(140)` to `HIGH(nau deck spot)`.
  - 'sail': `HIGH(pathPoint(200))`.
  - 'diveIn': eased interpolation from `HIGH(pathPoint(200))` to `cameraPose(200)`.
  - `HIGH(p)` is `{position: p + (0, 45, 30), target: p}`. Easing is `easeInOut(t) = t<.5 ? 2t² : 1−(−2t+2)²/2`.
